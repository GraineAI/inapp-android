## 0.14.4

- **`startWorkflow`: your app starts a workflow.** `GraineInApp.startWorkflow(workflow, data, idempotencyKey, done)` starts one of your outreach workflows for the signed-in user (the workflow needs **Your app can start this** on), with the fields the workflow allows — never who the run is for, never where it sends. It answers a `GraineWorkflowRun` (`runId`, `workflowId`, `alreadyRunning`) to `done`: the user's run already under way comes back (`alreadyRunning`), never a second. Every call carries an idempotency key — yours, or one the SDK makes — and a request that got no answer is asked once more with it, never twice started. New codes: `GraineErrorCode.NOT_ALLOWED`, `NOT_VERIFIED`.
- **Calls hold on through a weak or changing network.** When a call's connection drops — a lift, a tunnel, Wi-Fi to mobile data — the call now reconnects itself inside the same call and waits for the network to come back, instead of ending: it ends as dropped only after about 15 seconds without audio while the phone has a network (longer on a slow connection). A call whose audio does not start right after it is answered is reconnected the same way before it moves to the fallback connection, which is now used only when the call's own connection truly cannot carry audio.
- **Slow and restrictive networks connect.** On a slow connection the SDK waits longer before giving up; a call the network loses on the way is placed again, up to twice, once the phone has a network; and on a network that blocks some kinds of traffic, the next attempt uses only the routes that network allows.
- **Your app and your users.** Two protections an agent can switch on in its dashboard, each with a report-only stage and each off until turned on. Every request now says which app it is (the package name and the SHA-256 of its signing certificates), so an agent with *Only my apps* turns other apps away. With *Require a verified app*, the SDK proves the app with Play Integrity in the background — add `implementation("com.google.android.play:integrity:1.4.0")`; the SDK only compiles against it — keeps the app pass for 24 hours and renews it when under six hours remain; `prepareAppVerification` proves it on first launch. A debuggable build sends a debug token instead, logged once per install, to register on the agent (`debugTokenMode`, `debugToken`). With *Verified users*, `identify(traits, memory, identityToken)` sends your server's HMAC or your sign-in's JWT inside the identity only; `setIdentityToken` replaces it and `identityTokenRefresher` lets the SDK ask for a fresh one. `verification` (with `addVerificationListener`, and `verificationFlow` with coroutines) says what Graine has proven. New error codes: `APP_NOT_ALLOWED` (final), `APP_NOT_VERIFIED` and `IDENTITY_UNVERIFIED` (the SDK proves the app, or refreshes the token, and tries once more first). Nothing changes for an agent with neither on.
- **Server tokens.** `GraineConfig.tokenProvider` (`GraineTokenProvider { done -> … }`, or `GraineTokenProvider.suspending { … }`) fetches a short-lived token your server mints for the signed-in user (`POST /v2/client-tokens`), and every request to Graine carries it. The SDK asks at start, shortly before the token expires (with jitter, backing off after a failure, never while the app is in the background), when a call rings and when Graine refuses a token; a new conversation waits at most 10 seconds for a fresh one, and a token that expires never ends a live chat or call. Without a provider nothing changes.
- **New codes:** `TOKEN_REQUIRED`, `TOKEN_INVALID`, `TOKEN_EXPIRED` (the SDK has already asked for a fresh token and tried once more), `TOKEN_SCOPE` and `KEY_REVOKED` (final: update the app with the agent's new key), and `BOT_CHECK_FAILED` (websites only). `GraineError.reason` carries the server's word beside the code (`scope`, `user`, `signature`…). A chat refused for its token or key fails with `GraineChat.error` and does not retry by itself; a call fails with the code at the start of its error.
- **React Native and Flutter:** `GraineCallsHost.setClientToken(token)` and the `needClientToken` event bridge their own token managers to the native call engine.
- **The agent waits for the phone's audio.** A call over WebRTC tells Graine once the speaker is playing, so the agent's greeting is never spoken before the user can hear it — on calls the user places, rings they answer and redials alike. Update `inapp-android-rtc` beside `inapp-android`.
- **The right reason while the agent's settings load.** `memories()`, `forgetMemory()`, `scheduleCall`, `scheduledCalls`, `cancelScheduledCall`, a new conversation and past sessions wait for the agent's settings (a screen opened right after launch no longer says "Nobody is signed in" to a signed-in user) and, when they could not be loaded, hand on that reason — `unavailable`, `network`, `invalid_key` or `origin_refused`, with Graine's sentence; the next call loads them again. `identity_required` names the trait the agent identifies users by.
- **Booking says "not yet".** While a user is identified and the agent's settings are still to come, `bookingUnavailableReason` is `not_loaded` and the booking sheet never asks them to sign in. Read booking again in `GraineListener.onSessionReady` and after `identify`.
- A bare HTTP 500 now reads as `unknown` (`http_500`), as on iOS; 502, 503 and 504 are `unavailable`.
- **A request is answered only for the user who asked.** `memories()`, `forgetMemory()`, `scheduleCall`, `startWorkflow`, a new conversation and `chat.sessionTranscript` asked for one user, who signs out — another user signing in on the phone — before the agent's settings arrive, hear `IDENTITY_REQUIRED`: another user's memories are never forgotten or shown, nor a call booked in their name.
- **A memory choice is the user's it was made for.** A choice made before the agent's settings arrived, or taken on by an agent made later, is never filed for the next user on the phone — it could turn their "don't remember me" into "remember me".
- `reportEvent` and `track` write NaN and infinity in their data as `null`: they no longer throw `JSONException` into the app, or lose the event on the chat.
- **The same user written another way is the same user.** Re-identifying a user spelt another way — `Asha@Example.com` then `asha@example.com`, a phone with and without its country code — no longer signs them out (unlinking this phone from their booked calls), restarts their chat or loses their memory choice: users are compared as Graine keys them.
- **One rule for a refusal's code, on every SDK.** A code Graine sends wins; otherwise 400/422 `INVALID_REQUEST`, 401 `INVALID_KEY`, 403 `ORIGIN_REFUSED`, 404 `NOT_FOUND`, 429 `RATE_LIMITED`, 502–504 and the CDN's 520–524 `UNAVAILABLE`, anything else `Unknown("http_<status>")` — before, a 501 read as unavailable and a 409 as invalid_request.
- **`reportEvent` data never renames the event.** In the chat and on a call the name and detail are the call's own, the pacing keys sit at the event's level and everything else travels under its `data` (a `data` "detail" used to replace the detail in the chat, and a `data` "name" renamed the event on a call).

The voice bar's sheet and panel now offer New conversation as the window above the bar does.
- A multi-select answers with its button's label, then the names — "Taken: Morning and Evening" — where it said "Let's taken Morning and Evening."; it is the user's own line in a text chat.
- **Conversations continue.** A signed-in user who comes back finds the chat where they left it: the chat restores the earlier conversation the server sends when it opens (no welcome then — the user types next), followed by anything still waiting to be sent. `GraineChatTurn` gains `restored` and `channel` (`GraineChatTurn.Channel`: `CHAT`, `VOICE`), appended with defaults so Java callers compile as before. The chat window draws a day line where the day changes (Today, Yesterday, a date) and an earlier call as one "Voice call · 6:05 PM" row, never its transcript; the starters are not offered on a conversation that continues. `forgetMemory` also clears the chat on screen — only once it succeeded. Restored lines never reach `onChatMessage`.
- **A new conversation.** `chat.newConversation(done)`: the chat hangs up, Graine lets go of the conversation it kept for this agent and user, the chat clears and opens fresh, with the welcome and the starters; memories are untouched. The chat window's header offers it (a compose icon, `compose` in the SDK's icons) while an earlier conversation is on screen.
- A multi-select list's button says "Pick 2 more" — not "Pick 2 more to taken" for a list whose button says Taken. A full-screen component that arrived in the chat no longer says "Still listening": that footer is a call's.

- **A bigger chat window.** The dashboard sets how big the voice bar's chat opens (Embed & Widgets → Appearance → Chat window → Window size): Compact, the window above the bar as before; Large, a sheet over most of a phone (the app dimmed behind it, a handle to drag it closed, Back too) or a 420 dp panel in a tablet's corner; Full screen, the whole screen with the chevron leading the header. `GraineConfig(chatSize = …)` chooses for the app, and `chat.open(size)` for one open — which also moves a voice bar on screen to the chat. `GraineChatSize`, `GraineChat.openedSize`, `ChatTokens.size`. Still no dependencies: the sheet is the SDK's own.
- `GraineCallsHost` says which agent each call is with: `agent` (the agent's name) on the snapshot, `incoming`, `outcome` and `action`.
- **Several agents in one app.** `GraineInApp.init(application, config, name = "sales")` makes another agent beside the default one; `GraineInApp.get(name)`, `find(name)` and `all` reach them. Each agent has its own session, chat, voice bar, actions, and scheduling and memory calls, sent with its own key; the install id, who the user is (`identify` on one is for all, `identify(null)` signs out of all), the memory choice, the screen and the call engine are the app's. Views take the agent: `GraineAgentBarView.graine`, `GraineChatView.source = GraineInApp.get("sales").chat`, `GraineChatActivity.open(context, agent)`, `GraineWidgetView.graine`, `GraineLauncherView.graine`. `calls.startCall(activity, reason, variables, agent)` places a call with that agent, `calls.callAgent` says which agent the call in progress is with, and a ring Graine sends rings with the agent its `agent_id` names (else the default, with a warning in the log), in that agent's design — kept per agent for a cold start. The device is registered with every agent's key. One conversation at a time across every agent. `GraineCallsHost` (React Native and Flutter) takes `agents: {name: {publishableKey, baseUrl?}}` in its options and `agent` in `startCall`. An app with one agent changes nothing.
- **Who the user is, and memory.** `identify(traits, memory)`: the trait the agent's Identity setting names (`user_id` unless the dashboard chose `email`, `phone` or a custom one) is how Graine tells your users apart, so the agent can remember a user across conversations and ring them back. It travels only with the SDK's own requests to Graine — never as a prompt variable beyond the trait itself, never in a log. `memory = false` turns memory off for that user, and the choice is kept on the install. `setMemory(enabled)`, `memories { list, error -> }` (what the agent remembers about the signed-in user, for your privacy screen), `forgetMemory { deleted, error -> }`, and `identify(null)` signs out — so does identifying a different user: the device is released for the last one and their chat is cleared. The identifying trait itself is kept out of prompt variables and the screen context. `installId` is a random id made on first launch, kept in the app's no-backup storage (a restored phone is a new install).
- **Text chat.** `GraineInApp.get().chat` is a real conversation with the agent: the same screen context, actions and components as a call, one bubble per agent turn, a typing indicator while a reply is on its way, lines typed while connecting sent when it connects, and reconnection by itself after a drop. The voice bar follows the dashboard's mode (voice, chat or both) and switches between them — **an agent set to "both" (the default) now offers the chat beside the call**; set `bar.chat = null` for the call alone. `GraineChatView` and `GraineChatActivity.open(context)` show the chat as a whole screen, in the brand's chat design: header (surface or accent), avatar, title and subtitle, a dotted thread, the empty chat, starters, timestamps, composer — and an **Upcoming calls** card with the user's booked calls (the time in their zone, Cancel). `ChatSource` is public, for a conversation the app runs itself.
- **Scheduled calls.** `schedulingRules` (who may book, `earliest(now)`, `latest(now)`, the ring's length and call name), `scheduleCall(at, reason) { call, error -> }`, `scheduledCalls { calls, error -> }`, `cancelScheduledCall(id) { status, error -> }`. A `GraineScheduledCall` carries `status` (`GraineCallStatus`) and `source` (`GraineCallSource`), `isUpcoming` and `canCancel`. Booking switched off, too soon or too far is refused on the device before any request; every refusal is a `GraineError(code: GraineErrorCode, message, retryAfterSeconds)`.
- **Graine rings your users.** With your push credentials uploaded in Workspace settings → In-app calling, two lines in your `FirebaseMessagingService` are all it takes: `GraineCalls.onNewToken(this, token)` and `GraineCalls.handlePush(this, message.data)`. The SDK registers the device (on every new token, when what it says changes, else at most once a day), rings calls the agent booked ("Scheduled call") exactly as your own pushes ring, and reports what became of each. Every call ticket now carries the call's id and who the user is, so the call record and memory follow the user.
- **The call screen is the brand's.** `GraineCallActivity` is drawn from the design's call tokens in six moments — a scheduled call ringing, any other call ringing, connecting, on the call, ended, missed: background (or gradient), the avatar (logo, glyph or initials, in its shape), every colour and status word, the controls in the design's order, the end button round or as a pill, captions and timer on or off, a halo while it rings and the avatar growing while the agent speaks. The ring is the brand's too: `graine` and `soft` are tone patterns the SDK plays on the ringtone stream (silent mode and Do Not Disturb silence them as they silence the phone's own); `system` is the phone's ringtone, and a ringtone set in `GraineCallsConfig` still wins. The last design is kept on the device, so a push that wakes a closed app draws it too (before any session, Graine Classic's). A ring nobody answers leaves the screen on "Missed call" with **Call back**, and a missed-call notification with the same action.
- **Screen context, as on React Native.** The first change goes out at once and later ones at most every 400 ms (a screen updated on every keystroke used to wait until it stopped changing); a screen's own list of actions is narrowed to the ones this build registered; `updateField`, `removeField` and `clearScreen(id)`; taps on labelled controls are noticed by themselves (`GraineConfig.captureTaps`, on by default) and `tap(name)` reports one; `track(name, data, coalesce)`; `reportEvent` reaches whichever conversation is live, the chat included.
- `GraineListener.onChatState` and `onChatMessage`; the chat's `messages` are `GraineChatTurn`s (`id`, `role`, `text`, `at`, `delivery` — sending, sent, failed — `proactive`, `component`); `GraineCallOutcome` also carries `callId`, `outcome`, `reason`, `durationSeconds` and `hosted`; `SessionConfig.identity`, `memoryEnabled` and `schedulingRules`; `ThemeTokens.chat` and `call`; `Retry-After` honoured.
- `GraineCallsHost.onNewToken`, `setMemory` and `installId` for the React Native and Flutter packages (the React Native module gains `onNewToken`, `setMemory` and `getInstallId`, so every SDK on a device shares one install id).
- Still no runtime dependencies.

## 0.6.2

- **A call goes on hold when the phone takes its audio** — a phone call ringing, another app's call or player: nothing the customer says is sent and nothing the agent says is played until the audio comes back, and then the call carries on. A notification sound changes nothing. **If the customer answers a phone call during the hold, the agent's call ends** (`ended`, `local`), as iOS's End & Accept ends it.

## 0.6.1

- **Calls follow the headset**, as a phone call does: a Bluetooth headset first (LE audio, hands-free, hearing aids), then a wired or USB headset, then the earpiece. Turning the loudspeaker off brings the call back to the headset, and the choice is made again whenever a headset is switched on, off, plugged in or pulled out. No new permission.
- **A repeated push for the call in progress is ignored**, as on iOS, instead of being reported `missed` while that call goes on.
- **A microphone that stops mid-call is rebuilt once**; if it cannot be, the call ends — `ended` with `failed` and "The microphone stopped working." — instead of staying up with the customer silent.
- `GraineCallsHost` takes a `debug` option, so React Native and Flutter apps can turn on the SDK's debug log for calls.

## 0.6.0

- **Calls like WhatsApp**: `GraineInApp.get().calls`. Your agent rings the customer — hand your FCM data message (`type: "agent_call"`, `call_id`, `reason`, `caller_name`, `variables`) to `calls.handlePush(data)`, and the phone rings with a call notification (the ringtone, Answer and Decline, CallStyle on Android 12+) and a call screen over the lock screen. Or the customer calls the agent with `calls.startCall(activity, reason, variables)`.
- **The call keeps going with the screen off**, with its audio in your app — the microphone with the platform's echo canceller, the earpiece or speaker — inside a microphone foreground service, with an ongoing-call notification and Hang up.
- **Outcomes for your server**: `GraineCallListener` reports the call's state, captions and speech, and its outcome with the call's id — answered, declined, missed (30 s by default, or busy), ended (local, remote, failed) or failed.
- `GraineCallsConfig` sets the name, the status-bar icon, the ringtone, your own call screen and the ring timeout. The library's manifest declares the call screen, the service, the receiver and their permissions.
- Starting a call ends a conversation in the assistant bar, and the bar cannot start one while a call is live.
- `SessionConfig.wsHost`, filled in by the server.
- `GraineCallsHost`, for the React Native and Flutter call packages: the calls driven in plain values (maps, lists, strings), the options kept for a cold start, the call as one snapshot, and the agent's actions answered from JavaScript or Dart. A native app keeps using `GraineInApp.get().calls`.
- `GraineInApp.registerDeferredAction(name) { args, answer -> }`: an action answered later — after a network call, a confirmation, another screen — held to the same six seconds and the first answer.
- Still no runtime dependencies.
- The library's manifest adds what a call needs. On Android 14+, Google Play asks apps that declare `USE_FULL_SCREEN_INTENT` or `FOREGROUND_SERVICE_MICROPHONE` to explain them; an app that does not use calls removes those two permissions and `ai.graine.inapp.GraineCallService` with `tools:node="remove"` (snippet in the Android guide).

Guide: [In-app calling](https://www.graine.ai/docs/in-app/calling).
